## Technical repairs

- Complete Open Graph and Twitter metadata on all public pages, preserving exact existing page titles and descriptions.
- Remove build-time fabricated `lastModified` dates from the sitemap.
- Link legal documents directly to their canonical root routes instead of the intermediate `/legal/` redirects.
- Redirect the duplicate `www` hostname to the existing apex canonical origin, preserving paths and query strings.
- Inline the existing CSS through Next's supported build option to remove blocking stylesheet round trips.
- Serve immutable prerendered pages through OpenNext's supported cache interception, avoiding full Next server startup for those requests. Dynamic jobs and submission routes retain their existing runtime behavior.
- Apply static-asset headers through Cloudflare's `_headers` file. Framework response headers do not apply to the ASSETS binding. Build-hashed fonts and chunks are immutable; unversioned artwork has a bounded one-hour cache.
- Deliver the existing client artwork as lossless WebP with intrinsic dimensions.
- Remove the inert homepage hero/scroll coordinator dependency. The approved hero is already static.
- Preserve tactile button feedback through native Web Animations without loading unrelated ScrollTrigger code.
- Cache successful normalized public jobs responses for five minutes through the existing Cloudflare Cache API. The OpenNext static-assets cache cannot perform runtime revalidation. Errors and form submissions are not cached. Upstream job requests are bounded to 15 seconds.
- Route job Apply links to the career form, retaining the selected role in the submission.
- Require explicit upstream `ok:true`. Missing CV/email flags remain unknown instead of being reported as successful. Reject oversized message payloads before normalization can truncate them into validity.
- Follow Google ContentService response redirects explicitly as credential-free GET requests. Send the original POST once, reject unrelated destinations and POST-preserving redirects, and bound the exchange. Reject non-object JSON and retain only sanitized transport diagnostics for malformed responses.
- Expose the existing script's audit outcome separately from business persistence. A failed audit does not prompt duplicate submission. Server error logs avoid upstream URLs and response payloads.
- Retain every standard Lighthouse JSON and HTML run, including failed/baseline phases, without changing scoring or throttling.

## Evidence rules

A website receipt proves API completion. Sheet readback proves storage. Drive permission metadata proves that a test file was not publicly shared. A mail-send flag proves accepted sending, while inbox readback proves receipt for that mailbox. These are separate claims.

Lighthouse 100 does not establish search ranking or Google indexing. It is a lab score under the recorded standard profile. Retain repeated runs and report variation honestly.

## Form receipt follow-up

A completed receipt can now be recovered through one authenticated GET on the same Google web app when its original response cannot be read. The script reuses the validated website-generated ID for new submissions and caches only ID, destination sheet and technical success flags for up to 30 minutes. It stores this after the mandatory writes, notification and audit processing. A cache miss, early eviction or unreadable lookup remains a failure. The website never repeats the submission POST, requires the matching receipt ID, and shares its original deadline and three-redirect bound across both response exchanges. Historical IDs and existing credentials, workbooks, CV folder and recipients remain unchanged.

The www root redirect has an explicit rule before the wildcard redirect. This avoids a literal `:path*` destination when the native prerender adapter has no path capture.

Live response diagnostics also observed a transient HTTP 404 on the Google ContentService response URL after the enquiry had already been stored and emailed. The adapter now re-reads only the approved response GET, at most twice after 500 ms and 1 second, within the original 90-second deadline. It retains the redirect bound and never retries the submission POST or treats a stored-row observation as an API receipt. Exhausted response reads remain failures. Tests cover recovery through a subsequent redirect, bounded exhaustion, application-error JSON and hostile redirects during recovery.

Fast autofill previously received an `ignored` anti-spam acknowledgement and the client displayed a saved receipt. The client now waits the actual remaining minimum fill interval before its single POST, with a synchronous in-flight guard. It requires an explicit success and a nonempty receipt other than `ignored`. The server keeps its minimum-time guard and returns an honest 400 for requests that arrive too early. Existing copy remains unchanged. A mocked browser regression verifies two immediate submit events cause one request with form age at least 1500 ms, and that an ignored receipt shows the existing error while retaining fields. The client/server clock comparison remains an inherited timing limitation.
